## 세 개의 슬롯머신 앞에서

서로 다른 당첨확률의 슬롯머신 세 대가 있다. 각 머신의 당첨확률은 20%, 30%, 15%로 세팅돼 있지만 일반 사용자에게 확률은 공개되지 않는다.

기계별 당첨률 차이를 추정하고 불확실성을 따지는 것이 목표라면 가진 코인을 고르게 나누어 결과를 비교할 수 있다.
하지만 목표가 **100번 동안 최대한 많이 당첨되기**라면 선택 방식을 다르게 고려 해야한다.

당첨이 잘 되는 기계를 더 자주 이용하면서, 초반의 당첨이 우연인지 확인하려면 다른 기계도 시도해봐야 한다.
이를 `탐색(Exploration)`과 `활용(Exploitation)`이라 한다.

다중 선택지 밴딧(Multi-Armed Bandit, MAB)의 이름을 그대로 풀면, 서로 다른 당첨 확률을 가진 손잡이(Arm)가 여러 개 달린 가상의 슬롯머신 한 대에 가깝다. 슬롯머신을 `One-Armed Bandit`이라고 부르던 데서 유래한 표현이다.

다만 실제 슬롯머신은 보통 손잡이가 하나라서, 설명에서는 이를 당첨 확률이 서로 다른 슬롯머신 여러 대로 나누어 표현한다. 손잡이 하나를 고르든 머신 한 대를 고르든, 매번 서로 다른 확률을 가진 선택지 하나를 고른다는 문제는 같다.

이처럼 MAB는 선택을 반복하면서 누적 보상 확률을 높이는 시도를 반복한다.

## 슬롯머신을 CTA로 생각해보자.

앱의 메인 버튼 문구를 두 가지로 준비했다고 가정하자.

- CTA A: `무료로 시작하기`
- CTA B: `지금 시작하기`

사용자가 클릭하면 보상은 `1`, 클릭하지 않으면 `0`이다. 슬롯머신의 손잡이는 CTA가 되고, 당첨 여부는 클릭 여부가 된다.

| 용어                      | 뜻                                  | CTA 예시         |
| ------------------------- | ----------------------------------- | ---------------- |
| 선택지(Arm)·변형(Variant) | 고를 수 있는 버전                   | CTA A or B       |
| 행동(Action)              | 선택지 하나를 고르는 일             | CTA B 노출       |
| 라운드(Round)             | 선택과 보상이 일어나는 한 번의 기회 | 방문자 한 명     |
| 보상(Reward)              | 선택 뒤 관측한 결과                 | 클릭 1, 미클릭 0 |
| 정책(Policy)              | 다음 선택지를 고르는 규칙           | A or B (or more) |
| 기간(Horizon)             | 전체 선택 기회의 수                 | 방문자 100M      |

이 글에서는 Variant 하나가 Arm 하나에 대응하고 방문자는 한 번만 선택 대상이 된다고 단순화한다.

```bash
CTA 선택 → 노출 → 클릭 관측 → 정보 갱신 → 다음 CTA 선택
```

## MAB는 어떤 머신러닝일까?

지도 학습(Supervised Learning)은 정답(label)이 포함된 데이터 셋으로 모델을 훈련하는 머신러닝 기법이다.
모델에게 무엇이 정답이고, 오답인지 알려줘야(지도, supervised) 하기 때문에 사전 준비물(데이터)이 필요하다.
반면 MAB는 완성된 정답지가 없다. 지도학습은 정답 레이블로 입력과 출력의 관계를 예측하지만, MAB는 순차적 의사결정 과정에서 탐색과 활용의 균형을 맞추며 최대 보상을 찾는다.
여기서 순차적 의사 결정이란 매번 CTA 선택 보상을 토대로 다음 선택을 배우는 방법을 의미한다.

운영과 학습이 같은 시간축에서 일어나는 온라인 의사결정(Online Decision-Making) 문제다. 상태 전이가 복잡한 일반 강화 학습보다 단순한 형태로 볼 수 있다.

A를 보여주면 A의 클릭 여부만 알 수 있다. 같은 사용자에게 B를 보여주었다면 클릭했을지는 모른다. 선택한 행동의 결과만 관측하는 이 제약을 부분 피드백(Partial Feedback)이라고 한다.

클릭을 보상으로 삼으면 CTA의 기대 보상은 장기적인 클릭률(CTR)이다. 여기서는 설명을 위해 클릭률이 실험 중 변하지 않는 정상 환경(Stationary Environment)을 가정한다.

## A/B 테스트와 무엇이 다를까?

여기서는 전통적인 고정 배분 A/B 테스트와 비교한다. 트래픽을 50:50처럼 고정하고 데이터를 모아 효과 차이를 추정하고 검정하는 방식이다.

MAB는 결과에 따라 선택을 바꾼다. 성과가 좋아 보이는 CTA를 더 자주 보여주어 실험 기간의 누적 보상을 높이려 한다.

| 구분          | 고정 배분 A/B 테스트 | Regret을 줄이는 MAB         |
| ------------- | -------------------- | --------------------------- |
| 주된 목적     | 효과 추정과 검정     | 누적 성과 최대화            |
| 배분          | 실험 중 고정         | 관측 결과에 따라 적응       |
| 좋은 CTA 활용 | 주로 실험 종료 후    | 학습하면서 확대             |
| 결과 해석     | 상대적으로 단순      | 적응형 배분으로 더 까다로움 |

![고정된 50대 50 A/B 배분과 시간에 따라 바뀌는 MAB 배분](ab-vs-mab.png)

_그림 1. A/B 테스트는 배분을 유지하고, MAB는 관측 결과로 다음 선택을 조정한다._

어느 하나가 상위호환은 아니다. 정확한 효과 추정이 중요하면 A/B 테스트가, 학습 중의 성과까지 중요하면 MAB가 더 잘 맞을 수 있다.

밴딧에도 최선의 Arm 식별만을 목표로 하는 문제가 따로 있다. 이 글은 실험 중 누적 보상을 높이고 Regret을 줄이는 설정을 다룬다.

## 탐색과 활용 사이에서

초반에 A와 B를 10명씩 보여주었더니 A는 2번, B는 1번 클릭됐다고 하자. 관측 클릭률은 A 20%, B 10%다.

지금부터 A만 보여주는 것은 현재 최선으로 보이는 선택에서 보상을 얻는 활용이다. 그러나 실제 클릭률은 A 5%, B 6%인데 초반 결과만 우연히 뒤집혔을 수 있다.

A만 고르면 B에 관한 데이터는 더 생기지 않는다. 덜 확인한 B도 시도해 정보를 얻는 탐색이 필요한 이유다.

![현재 선두 CTA를 고르는 활용과 덜 확인한 CTA를 시도하는 탐색](exploration-exploitation.png)

_그림 2. 활용은 현재 보상을, 탐색은 더 나은 선택을 발견할 정보를 얻는다._

활용만 하면 초반의 우연에 고착되고, 탐색만 하면 낮은 CTA에 트래픽을 낭비한다. MAB 알고리즘의 차이는 이 균형을 정하는 방법에 있다.

## 좋은 선택을 놓친 비용, Regret

처음부터 최선의 CTA를 알았던 가상의 정책을 Oracle이라고 하자. Oracle과 실제 정책의 기대 누적 보상 차이가 기대 누적 후회(Expected Cumulative Regret)다.

```bash
R_T = Tμ* - E[Σ(t=1..T) X_t]
    = E[Σ(t=1..T) (μ* - μ(A_t))]
```

`T`는 전체 라운드 수, `μ*`는 최선 CTA의 기대 보상이다. `A_t`는 t번째 선택, `X_t`는 그때 관측한 보상이다.

방문자 100만 명, 실제 클릭률 A 5%, B 6%라고 사후적으로 가정해 보자. 처음부터 B만 보여주었다면 기대 클릭은 60,000회다.

| 배분           | A 기대 클릭 | B 기대 클릭 |   합계 | 기대 Regret |
| -------------- | ----------: | ----------: | -----: | ----------: |
| A/B 50:50      |      25,000 |      30,000 | 55,000 |       5,000 |
| 가상 MAB 15:85 |       7,500 |      51,000 | 58,500 |       1,500 |

50:50보다 기대 클릭을 3,500회 더 얻으면서 A도 계속 확인한 셈이다.

![Oracle의 기대 누적 클릭과 실제 정책의 기대 누적 클릭 차이인 Regret](cumulative-regret.png)

_그림 3. Oracle과 실제 정책의 기대 누적 클릭선 사이 간격이 Regret이다._

`15:85`는 특정 MAB가 보장하는 비율이 아니라 가상 평균 배분이다. 위 클릭 수도 확정값이 아니라 주어진 클릭률에서의 기대값이다.

## 세 가지 알고리즘으로 CTA 고르기

알고리즘마다 다른 것은 다음 방문자에게 보여줄 CTA를 정하는 규칙이다. 선택 이후의 흐름은 같다.

```bash
정책 상태를 초기화한다

방문자가 올 때마다:
  기록으로 CTA 하나를 선택한다
  실제 노출과 선택 확률을 기록한다
  관찰 구간 뒤 보상 0 또는 1을 확정한다
  선택한 CTA의 상태만 갱신한다
```

### ε-greedy: 가끔은 무작위로 고르기

엡실론 그리디(ε-greedy)는 확률 `ε`로 모든 CTA 중 하나를 균등하게 무작위 선택하고, 나머지 확률에는 관측 클릭률이 가장 높은 CTA를 고른다.

CTA가 둘이고 `ε=0.1`이면 선두는 활용에서 90%, 무작위 탐색에서 5%를 받아 약 95% 노출된다. 다른 CTA는 약 5%다. 탐색 트래픽 전부가 후발 CTA로 가는 것은 아니다.

구현은 쉽지만 고정 `ε`는 데이터가 충분해진 뒤에도 무작위 선택을 계속한다. `ε`가 작으면 잘못된 초기 판단에서 벗어나는 데 오래 걸릴 수 있고, 크면 탐색 비용이 커진다.

### UCB: 덜 확인한 CTA에 보너스 주기

신뢰 상한(Upper Confidence Bound, UCB)은 관측 성과와 불확실성을 한 점수에 담는다. 보상이 0과 1 사이인 UCB1의 점수는 다음과 같다.

```bash
UCB_i(t) = X̄_i + √(2 ln t / N_i)
```

`X̄_i`는 CTA i의 평균 보상, `t`는 전체 선택 횟수, `N_i`는 해당 CTA의 선택 횟수다. 첫 항은 활용, 둘째 항은 탐색을 맡는다.

`N_i=0`을 피하려고 처음에는 각 CTA를 한 번씩 선택한다. 이 값은 낙관적으로 Arm을 고르는 점수이며, A/B 테스트의 p-value나 효과 추정용 신뢰구간이 아니다.

### Thompson Sampling: 가능한 클릭률을 뽑아 보기

톰프슨 샘플링(Thompson Sampling)은 클릭률을 하나의 값이 아닌 확률분포로 다룬다.

0 또는 1인 보상에는 베타-베르누이(Beta-Bernoulli) 모형을 쓸 수 있다. 각 CTA를 `Beta(1,1)`로 시작하고, 클릭이면 `α`, 미클릭이면 `β`를 1씩 늘린다.

클릭이 `s_i`번, 미클릭이 `f_i`번이면 후분포는 `Beta(1+s_i, 1+f_i)`다. 매 라운드 각 후분포에서 후보 클릭률을 하나씩 뽑고 가장 큰 CTA를 고른다.

관측이 적은 CTA의 분포는 넓어 가끔 큰 값이 뽑힌다. 이 과정에서 탐색이 생긴다. 한 번 뽑은 값은 해당 CTA가 최선일 확률이나 통계적 신뢰도가 아니다.

| 알고리즘          | 탐색 방식               | 장점                          | 주의점                       |
| ----------------- | ----------------------- | ----------------------------- | ---------------------------- |
| ε-greedy          | 확률 `ε`로 무작위 선택  | 단순하다                      | `ε`를 정해야 한다            |
| UCB1              | 적은 관측에 보너스 부여 | 선택 근거가 점수로 보인다     | 안정적인 0~1 보상을 가정한다 |
| Thompson Sampling | 후분포에서 표본 추출    | 관측량에 따라 탐색이 달라진다 | 모형과 사전분포가 필요하다   |

항상 우월한 알고리즘은 없다. 보상 형태, 트래픽, 설명 가능성, 운영 복잡도에 맞춰 고른다.

## Feature Flag와 연결하기

기능 플래그(Feature Flag)는 변형 정의·타겟팅·전달·롤백을 맡는다. MAB 정책은 보상 기록을 보고 다음 CTA나 배분 비율을 정한다.

둘을 연결하면 `선택 → 노출 기록 → 클릭 귀속 → 보상 집계 → 정책 갱신` 순서의 피드백 루프가 만들어진다.

![MAB 정책이 CTA를 선택하고 Feature Flag가 전달한 뒤 클릭 보상이 정책으로 돌아오는 흐름](feature-flag-bandit-loop.png)

_그림 4. 요청 시점의 전달·기록과 주기적인 집계·갱신을 나눈 피드백 루프._

실제 화면에 표시된 노출을 기록해야 한다. 전달에 실패한 CTA까지 분모에 넣으면 클릭률이 왜곡된다. 관찰 구간이 끝나기 전에 미클릭을 0으로 확정하면 늦게 온 클릭도 놓친다.

Feature Flag의 가중치만 바꾸면 MAB가 완성되는 것은 아니다. 보상이 정책으로 돌아와야 한다. 70:30 같은 누적 노출 비율이나 일반적인 운영 배분은 그 자체만으로 최선일 확률이나 통계적 유의성을 뜻하지 않는다.

의사결정 ID, Arm, 정책 버전, 선택 확률, 실제 노출과 보상을 연결해 기록한다. 반복 방문에서 문구가 바뀌면 혼란스러운 UI라면 관찰 구간 동안 사용자별 CTA도 고정한다.

## 우리 시스템에 적용한다면

다음은 설명을 위한 가상 설계이며 실제 도입이나 운영 사례가 아니다.

앱 메인 CTA를 A `무료로 시작하기`, B `지금 시작하기`로 둔다. 정책이 하나를 고르면 Feature Flag가 전달하고, 실제 노출 뒤 클릭은 1, 관찰 구간 내 미클릭은 0으로 기록한다.

한 노출에는 보상 하나만 귀속하고 선택한 CTA만 갱신한다. 이 정책이 높이는 것은 클릭이다. 구매나 장기 만족도까지 좋아진다고 단정할 수 없다.

## MAB의 한계와 안전장치

- 트래픽이 적거나 차이가 작으면 불확실성이 오래 남는다. 알고리즘을 바꿔도 없던 정보가 생기지는 않는다.
- 지연 보상이나 이벤트 누락은 잘못된 학습으로 이어진다. 한 CTA의 이벤트만 더 자주 빠지면 측정 오류를 성과 차이로 배운다.
- 고전적 MAB는 보상 분포가 안정적이라고 가정한다. 주말 효과나 유행 변화에는 별도의 Non-stationary Bandit이 필요하다.
- 적응형 배분 데이터에 일반 A/B 테스트의 p-value를 그대로 적용하면 해석이 어긋날 수 있다. 전용 추론 방법은 이 글에서 다루지 않는다.
- 클릭만 보상으로 주면 구매나 장기 만족이 낮아도 눈에 띄는 CTA를 선호할 수 있다.

운영에는 최소 탐색 비율, 배분 변경 폭 제한, 즉시 중단 스위치(Kill Switch)가 필요하다. 오류율·지연 시간·구매 취소 같은 보호 지표(Guardrail Metric)도 함께 본다.

이 안전장치도 잘못 정의한 보상이나 누락된 이벤트를 고쳐주지는 않는다. 정책보다 먼저 측정과 롤백 경로를 믿을 수 있어야 한다.

## 그다음은 Contextual Bandit

일반 MAB는 모든 사용자에게 평균적으로 좋은 CTA를 찾는다. 맥락적 밴딧(Contextual Bandit)은 선택 전에 관측한 사용자나 상황의 맥락(Context)으로 `맥락 → Arm` 관계를 학습한다.

신규 사용자에게는 설명이 분명한 A가, 기존 사용자에게는 짧은 B가 잘 맞을 수 있다. 단순히 집단을 수동으로 나누는 것과 다르며, 실제로 보여준 CTA의 보상만 받는 부분 피드백은 그대로다.

맥락이 많아지면 데이터와 모델, 개인정보·편향 관리도 복잡해진다. Contextual Bandit 자체의 효과도 A/B 테스트나 Holdout으로 평가해야 한다. 구체적인 모델과 수식은 후속 글에서 다룬다.

## MAB를 선택하기 전 체크리스트

| 질문                                       | 맞는 선택                        |
| ------------------------------------------ | -------------------------------- |
| 보상을 빠르고 명확하게 측정할 수 있는가?   | MAB에 유리하다                   |
| 같은 선택이 충분히 반복되는가?             | MAB에 유리하다                   |
| 학습 중 놓치는 보상도 중요한가?            | MAB의 목적과 맞는다              |
| 최종 효과를 정확히 추정해야 하는가?        | 고정 배분 A/B 테스트가 낫다      |
| 사용자마다 선호가 다른가?                  | Contextual Bandit을 검토한다     |
| 노출과 보상을 안정적으로 연결할 수 있는가? | 피드백 루프를 운영할 준비가 됐다 |

처음에는 고정 배분으로 노출과 보상 귀속부터 검증하는 편이 안전하다. 측정 흐름을 신뢰할 수 있을 때 MAB 정책을 연결한다.

효과 차이를 추정하고 불확실성을 검정하는 것이 목표라면 고정 배분 A/B 테스트가 가깝다. 배우는 동안 놓치는 클릭까지 줄이고 싶다면 MAB가 답할 수 있는 문제다.

좋은 선택은 알고리즘 이름보다 보상 정의, 정확한 피드백, 운영 안전장치에서 시작한다.
